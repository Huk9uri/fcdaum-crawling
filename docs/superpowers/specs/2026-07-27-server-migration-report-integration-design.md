# 서버 이관 업무 보고 통합 편집 설계

## 목적

FC다움 API 데이터 수집과 `review_analysis`는 서로 다른 프로젝트이지만, 동일한 서버 PC로 운영 환경을 이관한 하나의 업무로 보고한다. 중복된 서버 이관 절차는 한 번만 설명하고 프로젝트별 운영 방식과 검증 결과만 구분한다.

## 문서 구조

1. 자동화 프로젝트 운영 서버 이관
   - 공통 추진 배경
   - 대상 서버 및 프로젝트 비교표
   - 공통 서버 환경 구성 및 운영 전환
   - 프로젝트별 작업 스케줄러 설정
2. 프로젝트별 검증 결과
   - FC다움 수동 및 예약 실행 결과
   - `review_analysis` 설치 및 대기 상태
3. 최종 운영 상태
   - 서버 작업 활성화
   - 로컬 작업 비활성화
4. 향후 확인 계획
   - 최초 정기 실행
   - DB 및 로그 점검
   - 재부팅 및 자원 사용량 확인

## 편집 기준

- 두 프로젝트를 하나의 상위 업무로 묶는다.
- 프로젝트별 경로, 실행 주기, 실행 계정 및 검증 결과는 표로 비교한다.
- Python 설치, 가상환경 구성, 설정 파일 이관, 작업 스케줄러 등록, 로컬 작업 비활성화 등 공통 절차는 중복 작성하지 않는다.
- FC다움의 상세 DB 컬럼, PowerShell 명령어, UTF-8 로그 조회 명령어 및 UTC 변환 예시는 업무 보고에서 제외한다.
- 수집 건수, 종료 코드, 스케줄러 상태 등 완료 근거는 유지한다.
- `review_analysis`의 `0x41301`은 오류가 아니라 실행 중 상태임을 간단히 명시한다.
- 업무 보고 문체는 수행 내용과 검증 결과 중심의 서술형으로 유지한다.

## 완료 기준

- 상위 업무 제목이 하나만 존재한다.
- FC다움과 `review_analysis`가 같은 서버 이관 업무의 하위 항목으로 표현된다.
- 동일한 서버 구성 및 로컬 비활성화 설명이 반복되지 않는다.
- 두 프로젝트의 운영 주기와 검증 결과가 누락되지 않는다.
- 향후 계획이 프로젝트별 최초 정기 실행 확인을 포함한다.
