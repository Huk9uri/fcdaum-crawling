# FC다움 매장명 표준화 설계

## 목적

FC다움 API에서 서로 다른 형식으로 제공되는 매장명을 브랜드별 업무 표준에 맞춰 리포트, 문제항목, 품질미션에 동일하게 저장한다.

## 한촌 규칙

1. 앞뒤 공백을 제거한다.
2. 앞부분의 `한촌설렁탕`과 뒤따르는 공백을 제거한다.
3. 끝부분의 괄호 표기와 앞 공백을 제거한다. 예: `(양수)`.
4. 결과가 `점`으로 끝나지 않으면 `점`을 추가한다.

예시:

- `한촌설렁탕 부천까치울점` -> `부천까치울점`
- `인천삼산점(양수)` -> `인천삼산점`
- `천안두정점(양수)` -> `천안두정점`
- `인천영종도` -> `인천영종도점`

## 육수당 규칙

1. 앞뒤 공백을 제거한다.
2. 기존 `육수당` 접두어와 뒤따르는 공백을 제거해 지점명만 추출한다.
3. 지점명이 `점`으로 끝나지 않으면 `점`을 추가한다.
4. 최종값을 `육수당 {지점명}` 형식으로 저장한다.

예시:

- `안양비즈타워점` -> `육수당 안양비즈타워점`
- `육수당 가산이앤시타워점` -> 동일

## 예외 처리

- `NULL`은 `NULL`로 유지한다.
- 빈 문자열은 빈 문자열로 유지해 임의의 `점` 또는 브랜드명만 생성하지 않는다.
- 정의되지 않은 브랜드 코드는 앞뒤 공백만 제거하고 원본 매장명을 유지한다.

## 적용 범위

- `dbo.fc_daum_qsc_report.store_name`
- `dbo.fc_daum_qsc_report_issue.store_name`
- `dbo.fc_daum_mission.store_name`

Python 공통 정규화 함수를 세 API-DB 매핑에서 사용한다. 다음 실제 수집에서 기존 행의 매장명이 달라지면 기존 변경 감지 로직이 UPDATE한다.

## 테스트

- 한촌 접두어 제거, 괄호 제거, `점` 추가를 각각 검증한다.
- 육수당 접두어 추가·중복 방지와 `점` 추가를 검증한다.
- `NULL`, 빈 문자열, 미등록 브랜드 처리를 검증한다.
- 세 데이터 매핑에 동일한 규칙이 적용되는지 검증한다.
- 전체 자동화 테스트와 실제 재수집 결과를 검증한다.
