# 리포트 예상 처분 합계 저장 설계

## 목적

리포트별 문제항목에 포함된 예상 과태료와 예상 영업정지 일수를 합산하여 `dbo.fc_daum_qsc_report`에 저장한다.

## 컬럼

- `expected_fine_amount DECIMAL(18, 2) NOT NULL`: 문제항목 `fine_amount` 합계
- `expected_suspension_days INT NOT NULL`: 문제항목 `suspension_days` 합계

문제항목이 없거나 개별 값이 `NULL`이면 합계에는 0으로 반영한다.

## 집계 기준

집계 키는 `brand_code + report_no`다. 하나의 문제항목 행에 과태료와 영업정지가 모두 있으면 각각의 합계에 포함한다. 여러 문제항목의 값은 단순 합산한다.

## 수집 및 적재 흐름

1. 한 브랜드의 리포트, 문제항목, 품질미션 수집을 완료한다.
2. 수집된 문제항목을 `report_no`별로 집계한다. 브랜드는 한 번의 수집 단위로 이미 고정되어 있다.
3. 리포트 매핑 시 집계값을 `expected_fine_amount`, `expected_suspension_days`에 포함한다.
4. 리포트, 문제항목, 품질미션을 기존 순서대로 하나의 DB 트랜잭션에 저장한다.
5. 다음 수집에서 집계값이 변경되면 기존 변경 감지 로직이 리포트 행을 업데이트한다.

지원용 상위 리포트처럼 이번 수집에서 문제항목을 조회하지 않은 리포트는 기존 합계를 0으로 덮어쓰지 않도록 집계 대상 리포트와 지원용 리포트를 구분한다. 최근 수집 대상 리포트에 대해서만 현재 문제항목 합계를 저장한다.

## 기존 데이터 마이그레이션

두 컬럼을 nullable로 추가한 뒤 기존 `dbo.fc_daum_qsc_report_issue`를 `brand_code + report_no`로 집계하여 리포트에 채운다. 문제항목이 없는 리포트는 0으로 채우고 두 컬럼을 `NOT NULL`로 변경한다.

## 테스트

- 과태료와 영업정지가 여러 문제항목에 걸쳐 합산되는지 검증한다.
- `NULL` 값과 문제항목이 없는 리포트가 0으로 처리되는지 검증한다.
- 다른 리포트의 문제항목이 섞이지 않는지 검증한다.
- 지원용 상위 리포트의 기존 집계값을 0으로 덮어쓰지 않는지 검증한다.
- 리포트 INSERT/UPDATE 대상에 두 컬럼이 포함되는지 검증한다.
- DB 마이그레이션, 실제 수집, 재실행 시 미변경 판정을 검증한다.
