# FC다움 월별 기간 분할 백필 설계

## 목적

FC다움 API에 보존된 2024년 1월 이후의 리포트, 문제항목 및 품질미션 데이터를 한 번에 처리하지 않고 월별 독립 구간으로 나눠 안전하게 MSSQL에 적재한다.

현재 `--from-date`는 지정 시작일부터 실행 시각까지 모든 데이터를 한 번에 수집한다. 2024년부터 전체 기간을 처리하면 수천 건의 리포트 상세 및 문제항목 API 호출이 발생하고, 브랜드별 단일 트랜잭션이 커져 마지막 단계의 오류로 전체가 롤백될 위험이 있다.

## CLI

월별 백필은 다음 명령으로 실행한다.

```powershell
python crawling.py `
  --backfill-from 2024-01-01 `
  --backfill-to 2025-12-31
```

규칙은 다음과 같다.

- `--backfill-from`과 `--backfill-to`는 반드시 함께 입력한다.
- 날짜 형식은 `YYYY-MM-DD`이다.
- 날짜는 KST 기준이다.
- 시작일이 종료일보다 늦으면 실행 전에 차단한다.
- 종료일이 실행일보다 미래이면 실행 전에 차단한다.
- 백필 옵션과 기존 `--from-date`는 함께 사용할 수 없다.
- 옵션이 없는 정기 실행은 기존 최근 1개월 동작을 유지한다.
- 기존 `--from-date`의 시작일부터 현재까지 일회성 수집 동작도 유지한다.

## 월 구간 생성

입력 기간을 달력 월 경계로 분할하되 최초·최종 월은 사용자가 입력한 날짜를 존중한다.

예시:

```text
입력: 2024-01-15 ~ 2024-03-10

구간 1: 2024-01-15 00:00 ~ 2024-02-01 00:00 미만
구간 2: 2024-02-01 00:00 ~ 2024-03-01 00:00 미만
구간 3: 2024-03-01 00:00 ~ 2024-03-11 00:00 미만
```

사용자에게 표시되는 날짜 범위는 양 끝 포함 형식으로 출력한다.

```text
2024-01-15 ~ 2024-01-31
2024-02-01 ~ 2024-02-29
2024-03-01 ~ 2024-03-10
```

내부 비교는 시간 경계 오류를 방지하기 위해 반개구간 `[start, end_exclusive)`을 사용한다.

## 수집기 변경

`MonthlyCollector.collect()`에 선택적 `collection_end`를 추가한다.

- `collection_start`: 포함 하한
- `collection_end`: 제외 상한
- 리포트 기준 필드: `visitDate`
- 품질미션 기준 필드: `regDate`
- 항목 포함 조건: `start_ms <= value < end_ms`

API 목록은 최신순으로 정렬된다. 수집기는 다음 방식으로 동작한다.

1. 종료 상한보다 최신인 항목은 건너뛴다.
2. 구간 내부 항목만 수집한다.
3. 시작 하한보다 오래된 항목을 만나면 페이지 조회를 중단한다.
4. 구간에 포함된 리포트만 상세 및 문제항목 API를 조회한다.
5. 구간 내 품질미션이 구간 밖 과거 리포트를 참조하면 기존과 같이 부모 리포트를 보조 수집한다.

## 실행 및 트랜잭션 정책

백필은 오래된 월부터 최신 월 순서로 진행한다.

각 월마다 기존 `run_all_brands()` 흐름을 사용한다.

- 한촌설렁탕 1차 처리
- 육수당 1차 처리
- 실패 브랜드 1회 재시도
- 두 브랜드가 모두 성공하면 해당 월 완료
- 최종 실패 브랜드가 있으면 해당 월에서 전체 백필 중단
- 이후 월은 실행하지 않음

DB 트랜잭션은 기존처럼 브랜드별·월별로 커밋한다. 한 브랜드 실패 시 해당 브랜드의 해당 월만 롤백되며, 이미 성공한 이전 월과 다른 브랜드의 커밋은 유지된다.

별도 체크포인트 파일은 만들지 않는다. 동일 명령 재실행 시 기존 UPSERT 로직이 다음과 같이 처리한다.

- 기존 동일 데이터: 미변경
- 기존 변경 데이터: UPDATE
- 없는 데이터: INSERT

따라서 실패 후 동일 전체 명령을 다시 실행해도 중복 행이 생성되지 않는다.

## 로그

기존 일별 로그 파일에 월별 진행 상태를 추가한다.

```text
[백필 2024-01] 시작: 2024-01-01 ~ 2024-01-31
[한촌설렁탕] 리포트 ...
[육수당] 리포트 ...
[백필 2024-01] 완료
[백필 2024-02] 시작: 2024-02-01 ~ 2024-02-29
```

실패 시 다음 형식으로 기록한다.

```text
[백필 2024-02] 실패: 이후 월 처리를 중단합니다.
```

전체 성공 시 처리 월 수와 전체 기간을 출력한다.

## 오류 처리

- 날짜 입력 오류는 API 또는 DB 연결 전에 종료 코드 2로 종료한다.
- 월 처리 중 API 또는 DB 오류는 기존 브랜드 재시도 정책을 따른다.
- 최종 실패 월이 발생하면 종료 코드 1을 반환한다.
- 완료된 이전 월을 롤백하지 않는다.
- 계정정보, 비밀번호, 토큰 및 DB 비밀번호는 로그에 출력하지 않는다.

## 테스트 범위

### 날짜 및 구간 생성

- KST 날짜 파싱
- 윤년 2024년 2월 구간
- 월 중간 시작일과 종료일
- 연도 경계 분할
- 시작일과 종료일이 같은 하루
- 시작일이 종료일보다 늦은 경우
- 미래 종료일
- 백필 옵션 한쪽만 입력
- `--from-date`와 백필 옵션 동시 입력

### 수집 범위

- 종료 상한보다 최신인 리포트 제외
- 시작일 포함
- 종료일 다음 날 00:00 제외
- 구간 밖 최신 데이터만 있는 첫 페이지 이후에도 과거 페이지 계속 조회
- 시작 하한보다 오래된 데이터 발견 시 중단
- 리포트와 품질미션에 각각 올바른 날짜 필드 적용
- 구간 내 품질미션이 참조하는 구간 밖 부모 리포트 보조 수집

### 월별 실행

- 오래된 월부터 순차 실행
- 월별 시작·완료 로그
- 모든 월 성공 시 종료 코드 0
- 실패 월에서 이후 월 중단 및 종료 코드 1
- 이전 완료 월의 커밋 유지
- 일반 정기 실행과 기존 `--from-date` 회귀 테스트

## 운영 절차

초기 실행 권장 범위는 다음과 같다.

```powershell
python crawling.py `
  --backfill-from 2024-01-01 `
  --backfill-to 2025-12-31
```

실행 전 서버의 정기 스케줄 작업이 동시에 실행 중이지 않은지 확인한다. 실행 후 월별 로그, 브랜드별 DB 반영 건수, 최저 업무일자 및 업무키 중복 여부를 검증한다.

## 완료 기준

- 하나의 명령으로 입력 기간이 월별 독립 구간으로 처리된다.
- 최초·최종 월의 부분 기간이 정확히 적용된다.
- 종료일 포함 조건이 KST 기준으로 정확하다.
- 월별·브랜드별 기존 트랜잭션 경계가 유지된다.
- 실패 월 이후 처리가 중단된다.
- 동일 명령을 재실행해도 중복이 발생하지 않는다.
- 기존 정기 실행과 `--from-date` 동작이 변경되지 않는다.
- 전체 자동화 테스트가 통과한다.
