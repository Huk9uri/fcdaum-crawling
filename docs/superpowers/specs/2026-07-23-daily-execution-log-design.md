# FC다움 날짜별 실행 로그 설계

## 목적

DB 데이터가 변경되지 않아 `updated_at`이 갱신되지 않는 실행도 운영자가 확인할 수 있도록, 수집 프로그램이 실행될 때마다 날짜별 로그 파일을 남긴다.

## 저장 위치와 파일명

- 프로젝트 루트의 `logs` 디렉터리를 실행 시 자동 생성한다.
- 실행 시작 시각의 KST 날짜를 기준으로 `logs/fcdaum_YYYY-MM-DD.log` 파일을 사용한다.
- 같은 날짜에 여러 번 실행하면 기존 파일을 덮어쓰지 않고 뒤에 추가한다.

## 기록 내용

- 실행 시작 및 완료 시각과 총 소요 시간
- 실제 수집 범위
- 브랜드별 API 수집 건수
- 브랜드별 DB 신규, 변경, 동일 건수
- 브랜드별 최초 실패와 재시도 결과
- 설정 오류, API 오류, DB 오류 등 최종 실패 내용
- 프로세스 종료 코드

비밀번호, 토큰, 쿠키, API 응답 원문 등 민감정보는 기록하지 않는다.

## 동작 방식

기존 `run_all_brands`의 출력 인터페이스는 유지한다. `main`에서 콘솔과 로그 파일 양쪽에 동일한 메시지를 전달하는 출력 객체를 만들며, 처리되지 않은 예외도 로그에 남긴 후 다시 발생시켜 비정상 종료 상태를 보존한다. 로그 파일 생성 자체가 실패하면 오류를 표준 오류로 출력하고 비정상 종료한다.

## 검증

- 고정된 실행 시각으로 예상 날짜의 로그 파일이 생성되는지 테스트한다.
- 기존 내용이 있는 파일에 새 실행 결과가 추가되는지 테스트한다.
- 성공, 설정 오류 및 처리되지 않은 예외의 종료 기록을 테스트한다.
- 전체 기존 테스트를 실행해 기존 수집 및 DB 반영 동작이 유지되는지 확인한다.
